## 为什么

用户需要按需接入多个模型 API，以同一批企业编码任务比较代码质量、响应速度与 token 消耗，形成可复算的分场景评分和综合评价。评测必须保留原始答案与运行证据，避免平台提示、人工修复及缺失统计造成误判。

## 变更内容

- 构建本地 Web 应用，提供模型配置、数据集管理、评测运行、结果对比四个页面。
- 提供评测编排 agent：解析评测意图、生成结构化运行计划、调用确定性执行器和判分器、解释结果。
- 初始化 10 个企业编码场景数据集，每个包含 1 个完整可执行种子任务，共 10 题；支持后续增加题目和导入自定义数据集。
- 直连用户配置的原始模型 API，采集首 token、总耗时、输入 token、缓存命中 token、输出 token。
- 提供可配置且冻结版本的评分维度和权重，生成逐任务、逐场景、多模型比较和综合评价。
- 首版仅比较 API 服务端点，不包含 TRAE IDE/CLI 模型执行、autocase 专项适配、模型自动发现、自动抓取题库或多轮编码工具代理。

## 范围解释与默认选择

1. “基座 API”按用户语境指直接调用模型服务，无 TRAE 工具、记忆、Skills、搜索、压缩等介入；不能据此声称在比较未经后训练的 base weights。
2. 首版适配 OpenAI Chat Completions 和 Anthropic Messages 两种协议；其他兼容服务经连接探针验证后使用，不承诺任意 URL 均可调用。
3. 种子任务首版统一使用 Python，数据库场景固定 SQLite；自定义任务首版支持相同运行环境，其他语言应明确提示尚不支持。
4. 10 个“数据集”定义为 10 个可扩展场景集合，各 1 个种子任务。初始成绩只能说明这些样本的表现，不能作为全行业能力排名。
5. 首版为单用户本地应用，无账号系统或多租户部署；页面绑定本机，执行生成代码必须使用受限容器。
6. 每个模型对每道题进行独立单次生成，默认重复 3 次；不将测试失败反馈给被测模型修复。各次结果均保留，不择优。

## 新增需求

### R1：自定义模型 API 配置

用户必须能够新建、编辑、禁用模型资源，填写显示名、协议、Base URL 或完整请求 URL、精确 model ID、API key、超时、输出限制以及服务支持的采样/思考参数。

- 完整 URL 与 Base URL 模式明确区分，不能重复拼接接口路径。
- API key 支持系统钥匙串持久保存、环境变量引用或当前会话输入，SQLite、结果导出和日志不保存明文密钥。
- 2026-10-23 用户追加需求：刷新、关闭会话或重启应用后，已保存密钥仍可使用。本机 macOS 使用原生钥匙串，用户显式点击保存/删除；不自动降级到明文文件、数据库或浏览器存储。Linux 当前仅支持环境变量/会话输入。
- 凭据优先级为会话输入 > 系统钥匙串 > 环境变量；绑定配置 ID、协议、URL 模式及完整服务地址，参数变更可复用，更换地址后需重新设置。探针、批次启动/恢复、控制计划和报告解释统一解析；运行期间凭据只留内存并继续精确脱敏。
- 所有模型在批次派发前校验凭据；公网地址默认要求密钥，本地 loopback 和保留测试域名允许无密钥。匿名自建服务可显式声明 `capabilities.api_key_required=false`；设置了环境变量引用的模型始终要求有效凭据。缺失时零请求，不消耗样本/请求预算。
- 保存失败显示固定错误信息并保留临时输入供重试；清除会话密钥不删除钥匙串，删除系统密钥同时清除该配置的会话覆盖。保存配置时检查已保存密钥，阻止将其粘贴到普通配置字段。
- 记录服务商、接入协议、参数、可见版本、配置哈希；无法确认实际模型版本时显示 unknown。
- 连接探针检测文本响应、流式响应与 usage 支持情况；探针单列费用与结果，不加入评分。
- 不支持的参数必须明确报错或标记待调整，不静默丢弃后声称已对齐。

#### 场景：增加企业网关模型

- **当** 用户填写兼容 API 地址和模型标识
- **则** 可以测试连接并保存配置，再将该模型加入多模型评测计划。
- **当** 服务只支持非流式
- **则** 允许执行，但首 token 指标为不可测，不用总耗时替代。

### R2：初始化 10 个企业编码场景

每道任务必须具备场景说明、独立系统提示词、明确需求、初始代码/公开夹具、输出协议、参考实现、隐藏评测代码、维度评分项、运行环境、时限、来源与内容哈希。参考实现和隐藏评测代码只在判分端使用。

种子任务为自建企业场景模拟题，不能声称来自真实客户生产事故。

| ID | 场景与需求 | 系统提示词要点 | 初始代码与隐藏评测重点 |
| --- | --- | --- | --- |
| C01 | 金额与折扣计算：修复精度和舍入 | 保持金额契约，使用 Decimal，明确舍入规则 | 订单计价函数；边界金额、折扣组合、输入不可变 |
| C02 | 库存并发扣减：防止超卖 | 单进程协作线程，原子提交，保留输入结构 | 扣减函数；可控交错、库存守恒、超额请求 |
| C03 | 支付回调幂等：重复事件只入账一次 | 固定 SQLite 事务接口，不吞掉数据库错误 | 回调处理模块；重复/并发事件、唯一约束、事务回滚 |
| C04 | 精确重构：SEARCH/REPLACE 补丁 | 指定唯一分隔符，只改允许范围，不输出解释 | 校验模块；唯一匹配、可应用、未授权修改、回归 |
| C05 | 遗留接口兼容：增加可选能力 | 保留函数签名和既有返回/异常契约 | 客户查询接口；旧调用、新选项、默认值、边界 |
| C06 | HTTP 客户端重试：应对限流与临时故障 | 使用提供的 transport/sleep，首次加三次重试 | 客户端包装器；429/5xx、不可重试错误、指数退避与上限 |
| C07 | SQL 查询优化：消除 N+1 | 保持查询结果和权限过滤，参数化 SQL | SQLite 查询模块；查询次数、结果一致、注入负例 |
| C08 | 权限缺陷修复：租户数据隔离 | 使用服务端身份上下文，默认拒绝越权 | 资源读取函数；跨租户、匿名、管理员和正常路径 |
| C09 | ETL 清洗：脏数据与去重 | 明确缺失值、日期、稳定去重与错误收集规则 | 清洗函数；多种脏数据、稳定顺序、输入不被修改 |
| C10 | 单测补充：覆盖业务缺陷 | 仅生成测试，使用给定 API，不修改生产代码 | 业务函数；正确版本通过、预设缺陷变体检出、测试可重复 |

#### 场景：验证种子任务

- **当** 发布内置数据集
- **则** 每个参考实现必须通过全部评测代码，至少一个针对性错误实现被拒绝；C10 的参考测试必须检出预定缺陷变体。
- **则** 并发任务通过可控调度制造竞争，不依赖随机压测恰好触发。
- **则** 每题明确异常契约、尝试次数、代码输出形式和边界条件，不在判分时追加隐含要求。

### R3：自定义数据集与版本管理

页面支持新建、编辑、复制场景/任务及导入导出。首版使用 JSON 元数据加 ZIP 代码包：元数据包含 schema_version、场景、系统提示词、需求、代码文件、输出格式、测试文件、维度评分项和预算。

- 提供可下载模板和字段校验结果；导入 ZIP 限制大小、文件数、路径，拒绝绝对路径、目录穿越和符号链接。
- 自定义测试属于待执行代码，导入不会自动在宿主机执行。
- 参考解与测试验证通过后任务才标记 ready；未验证任务只能预览或诊断执行，不进入正式综合分。
- 编辑产生新版本，历史评测继续引用旧快照；记录原始文件哈希。
- 系统提示词和需求严格按任务版本发送，不拼接未声明的全局“优化提示”。

#### 场景：上传一个重构任务

- **当** 用户导入合法的元数据及代码包
- **则** 能预览实际模型输入、评测项和权重，运行参考解校验，并纳入后续评测。
- **当** 缺少测试或评分项
- **则** 显示具体缺失项，不能用 agent 的主观判断替代可执行判分。

### R4：Agent 编排及公平执行

页面同时支持表单运行与自然语言指令，例如“比较 A、B 在库存和重构任务上的表现，每题重复三次”。

- 编排 agent 使用单独选择的控制模型，将指令转换为限定 schema 的计划；计划含模型、任务、参数、次数、并发、预算和权重。
- 未配置控制模型时表单运行仍完整可用；不得把固定工作流冒充已经调用了 LLM agent。
- 服务端验证 agent 的计划，界面展示实际任务和预计请求数，用户点击开始后执行；agent 不能自行新增付费调用或修改评分。
- 控制模型只接收任务目录和结果摘要，不接收 API key、参考解或隐藏测试。它的调用和费用单列。
- 每个任务使用全新请求，固定输入，不提供工具调用和历史记忆；样本顺序按保存的随机种子交错。
- 相同任务对所有模型发送语义相同的系统提示、需求和公开代码，保存协议映射及请求哈希。协议差异允许字段不同。
- 不声称相同温度/思考档位等于相同算力；记录模型支持范围，提供可比组与差异提示。
- 预检失败不开始批次；运行中的 API 错误、超时、截断均保留。网络重试默认关闭，可在计划中指定固定上限；重试不能择优覆盖。
- 任务状态包含 queued/running/completed/failed/cancelled；支持停止派发、取消在途请求、恢复未完成任务。响应丢失但可能计费的请求标记 uncertain。

#### 场景：评测完成后生成解释

- **当** 判分器输出已冻结结果
- **则** agent 可解释分场景优劣并引用具体 task/run ID，但不能修改数值或把未执行测试说成已通过。
- **当** 控制模型不可用
- **则** 确定性报表照常生成，解释功能显示不可用。

### R5：每次调用的性能及 token 指标

系统使用客户端单调时钟采集时间，UI 排队和容器测试时间不计入模型请求时延；它们另列。

| 字段 | 定义与展示规则 |
| --- | --- |
| 首生成内容耗时 | 发出请求至收到第一个非空生成内容事件，包含服务公开返回的推理内容；不把角色、心跳、空 delta 当 token |
| 首最终回答耗时 | 发出请求至第一个非空最终回答文本事件 |
| 总耗时 | 发出请求至响应流正常结束且接收最终 usage；失败时保存截至失败时长并标记未完成 |
| 输入 token | 服务端 usage 的输入总量，保留原字段和归一化口径 |
| 缓存命中 token | 服务端明确返回的缓存读取 token；无字段为 null，不是 0 |
| 输出 token | 服务端报告的输出量，并注明是否包含推理；公开推理 token 可单列 |

页面的“首 token”默认指首生成内容耗时，显示口径提示并同时提供首最终回答耗时。SSE 事件可能包含多个 token，该值是客户端可观测近似，不是服务器内部 token 生成时间。

- 首版规范化 OpenAI 的 prompt_tokens、completion_tokens、prompt_tokens_details.cached_tokens 等字段，以及 Anthropic input_tokens、cache_read_input_tokens、cache_creation_input_tokens、output_tokens；Anthropic 输入合计须按其不重复口径汇总。
- 不同服务的字段映射必须有配置版本和测试样例；未知供应商字段保留原文，不能猜测。
- 请求最终流式 usage；服务不支持时通过能力配置关闭该选项并标记缺失。
- 不以文本长度估算值冒充服务端计费 token；不把输入总量和缓存命中量相加造成重复计数。
- 返回早于正文的错误不产生有效首 token；非流式首 token 为 null。
- 每次实际请求保留独立 attempt 指标；逻辑任务总耗时另外包含重试间隔。批次给出均值、中位数、P95、样本量与缺失率。

#### 场景：服务未返回缓存用量

- **当** 成功响应只有输入和输出 token
- **则** 显示已知用量，缓存命中为“未提供”；不生成缓存命中率结论。
- **当** 流式连接中途断开
- **则** 保留已收到内容和可见耗时，任务标记失败，不把部分内容当正常完成。

### R6：客观判分与默认维度权重

采用编码评测常用关注维度，但不存在本项目可声称的统一“行业官方权重”。首版提供以下可编辑默认模板，所有权重在运行前冻结，合计必须为 100%：

| 维度 | 默认权重 | 证据 |
| --- | ---: | --- |
| 功能正确性 | 50% | 正常业务路径与需求验收测试 |
| 健壮性与边界处理 | 20% | 边界、异常、失败恢复测试 |
| 安全与数据完整性 | 15% | 权限、注入、原子性、守恒、无意外副作用等按题定义的测试 |
| 指令遵循与兼容性 | 10% | 输出格式、补丁可应用、签名/返回契约、允许修改范围 |
| 可维护性代理指标 | 5% | 预先明确的静态规则，如禁止重复实现、复杂度上限、限定公共接口；不冒充全面可维护性判断 |

每个测试断言/静态规则只能计入一个维度，分值和映射写入任务版本。内置任务必须提供各维度有效评测项；C10 功能维度以正确实现通过和缺陷检出衡量。

计算规则（所有维度分值为 0—100）：

- 单次质量分 = sum(维度权重 × 维度分)。
- 强制门槛：答案无法按已声明协议解析/应用，代码无法运行，或违反题目预先标记的关键数据安全不变量，则该次质量分为 0；诊断分仍展示。
- 任务分 = 同一任务所有独立样本质量分的平均值。
- 场景分 = 该场景所有任务分的平均值。
- 模型综合质量分 = sum(场景权重 × 场景分)，默认 10 个场景各 10%。
- 全通过率 = 全部强制验收项通过的样本数 / 已执行有效评测样本数。

模型/API 超时等执行失败计 0 并单列失败率；评测器自身故障为无效观测，不计能力分，阻止该批次形成完整正式排行，修复后重判。

自定义任务缺少某维度时必须显式定义自己的评分模板，不能自动把该维度补满；不同模板的结果不直接合并排名。

时延、token 消耗不混入默认质量分；报告并列比较质量与效率，避免“快速生成错误答案”获得高分。首版不推算价格或虚构性价比；可依据质量门槛筛选后比较耗时和 token 用量，但须说明 tokenizer 和推理统计不同。

#### 场景：用户修改权重

- **当** 运行前调整维度或场景权重
- **则** 预览总分算法并保存独立评分配置。
- **当** 运行后尝试调整
- **则** 产生新报告版本，不覆盖原分数，并显示属于事后分析。

### R7：判分执行、隔离与证据

- 2026-10-23 容器验证修复：依赖身份保护前先解析 `tempfile.gettempdir()`，使标准库惰性初始化不会误判为候选篡改；文件许可仅新增精确 `/dev/null`，支持 C10 subprocess.DEVNULL 丢弃输出。保留模块绑定、类方法、函数身份与防篡改检查。修复后判分版本为 `docker-python-v3`，旧证据及旧评分不覆盖。
- 生成代码、自定义测试和静态分析均在受限 Docker 容器运行，固定镜像版本、CPU/内存/进程数/超时，默认禁网、非 root，不传入模型密钥和宿主 Docker socket。
- 执行器由宿主编排，UI 不授予生成代码宿主文件访问；数据集文件只挂载必要路径。
- Docker 不可用时可以配置和导入数据，但动态判分显示 blocked，不能回退宿主直接执行。
- 首版统一 Python 运行环境；依赖在题目元数据中冻结，不允许被测代码临时联网安装。
- 保留输出原文、提取后的代码、提取规则、补丁、测试日志和维度证据。严格原始评分不自动修复答案。
- 不采集未公开推理过程，不要求模型披露内部思维链。

#### 场景：隐藏测试代码出错

- **当** 判分器出现与答案无关的执行错误
- **则** 标记 judge_error、展示日志、阻止用此结果判定模型能力；修复产生新判分版本。

### R8：多模型对比与综合评价

界面必须提供：

1. 场景 × 模型的分数矩阵、质量维度对比及综合质量排名。
2. 逐任务原始输出、首 token/总耗时、输入/缓存命中/输出 token、测试通过情况和失败证据。
3. 相同任务的答案并排查看，重复样本可切换，不只显示最佳答案。
4. 质量—延迟比较图、各模型 token 用量和缺失统计；输出量小不能直接解释为更强或更省钱。
5. 完整性提示：模型版本、题库版本、参数差异、样本量和未完成任务。
6. JSON/CSV 数据导出及本地 HTML 报告，报告导出转义模型输出，不能执行其 HTML/脚本。

仅在相同题库、评分配置、任务覆盖范围和预算组上正式排名。未完成批次显示“暂定”；缺失任务不能按成功处理或静默从分母删除。公共子集比较可另生成带标注的探索性报告。

提供按任务聚类重采样的区间估计；同题重复不能当成新的独立题。10 个初始任务下，结论必须标注探索性，不把小分差宣称为统计优势。

#### 场景：两个模型质量相近

- **当** 分数差异小且区间重叠
- **则** 报告不确定性，结合延迟和用量展示候选，不宣称某模型全面胜出。

## 修改需求

2026-10-23 用户追加产品体验优化，自主决策无需人工确认：
默认加载摘要，答案/原始响应/任务 JSON 编辑按需展示；报告版本列表仅读元信息，
导出在点击时生成；运行监控独立刷新，不定时重跑计划表单或付费动作。
顶部与侧栏导航及 URL 同步，窄屏卡片换行、侧栏默认收起。
后台 worker、冻结计划、完整原文、评分口径与密钥存储契约保留。
单测、页面集成、真实桌面/窄屏浏览器和性能基准须有证据。
四件套及验证记录在 `product-experience/`。

本次范围替代之前讨论的 TRAE/API 混合评测设想：被测模型全部通过用户填写的原始 API 调用。实现代码可在 TRAE 中开发，但 TRAE 不参与被测请求的提示或执行循环。
